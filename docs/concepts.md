# Понятия

Каждый термин руководства — одной строкой: что это и зачем. Остальные страницы
ссылаются сюда, а не определяют заново. [← Руководство](index.md)

## Зачем ядро

Один большой `CLAUDE.md` грузится в каждую сессию целиком: чем он длиннее, тем
меньше внимания модели достаётся каждому правилу, и нужное в момент коммита
правило тонет среди правил про деплой и логи. Ядро держит правила отдельными
файлами и подаёт каждое тогда, когда оно нужно, — а то, что нельзя пропустить,
останавливает до выполнения.

## Правила и подача

| Понятие | Что это | Зачем |
| --- | --- | --- |
| desk, `DESK_HOME` | каталог с правилами (по умолчанию `~/desk`) | одно место для всех правил, под git |
| правило | markdown-файл; во фронтматтере — когда подавать и что запрещать, ниже — текст для модели | правило и его запрет живут в одном файле и не расходятся |
| подача | хук кладёт текст правила в контекст модели (строки `[desk] …` в сессии) | модель видит правило, не открывая файл сама |
| ярус (`tier`) | крайний срок, к которому правило должно быть в контексте: `import` — всегда, `session` — со старта, `action` — к действию, `link` — только по ссылке | в каждую сессию идёт только то, что нужно всегда; остальное ждёт своего момента |
| триггер (`when:`) | событие, по которому приходит правило яруса `action`: команда, git-подкоманда, записываемый путь, реплика, скилл, MCP-инструмент | правило про коммиты приходит на `git commit`, а не висит в каждой сессии |
| общий триггер | условие с именем в `desk.yml` (`when: [mr]`) | одно условие на много правил; место переопределяет его своим инструментом |
| порция | часть правила до 12 КБ | Claude Code прячет вывод хука длиннее ~10 тыс. символов в файл с превью, и модель его не видит; крупное правило режется по разделам, остаток приходит со следующим вызовом |
| слот | один из четырёх запусков хука на старте сессии: слот 0 — шапка и строки, слоты 1–3 — по порции файлов `session` | одного вывода хука мало для старта — три слота файлов дают до трёх порций |
| вход сессии | всё, что модель получает до первого действия: ярусы `import` и `session` | его вес меряют, потому что он стоит в каждой сессии |

## Запреты

| Понятие | Что это | Зачем |
| --- | --- | --- |
| guard | проверка во фронтматтере: `deny` отклоняет вызов, `ask` спрашивает человека — до выполнения | правило яруса `action` приходит вместе с результатом вызова и на сам вызов уже не влияет; guard — влияет |
| gate | `gate: true` у триггера: первый такой вызов отклоняется вместе с текстом правила, повтор проходит | для правил, которые должны повлиять на выбор действия с первого раза |
| расширение (`ext/`) | Python-файл: своя проверка вызова, проверка для `desk lint` или `desk measure`, строки на событиях | что не выражается регуляркой |

## Контексты

| Понятие | Что это | Зачем |
| --- | --- | --- |
| контекст | каталог `contexts/<имя>/` со своими правилами, триггерами и репозиториями; активен по `git remote` или пути сессии | рабочие и личные правила не смешиваются |
| место | контекст места работы (работодателя); личный контекст — тоже контекст, но не место | правила работы уходят вместе с работой, общие остаются |
| переносимый слой (`portable`) | правила вне `contexts/` — без имён места | их можно унести на новую работу или опубликовать |
| слова места (`place-words.txt`) | имена работодателя, хостов, продуктов | правка, вносящая их в переносимое правило, спрашивает подтверждения |
| интерфейсы (`interfaces:`) | словарь допустимых имён файлов в `contexts/<место>/projects/<репо>/`: `local.md` — как поднять, `tests.md` — как гонять тесты, `deploy.md` — выкат… | у каждого репозитория одна раскладка: общее правило ссылается на «`local.md` проекта», и файл с этим именем везде значит одно и приходит одним ярусом |

## Замер

| Понятие | Что это | Зачем |
| --- | --- | --- |
| досягаемость (reach) | из сессий, где триггер правила сработал, — доля тех, где текст правила был в контексте модели | правило, которое не доходит, не работает; меньше 100 % — значит, триггер сработал, а правила в контексте не было (хуки не подключены, правило ждало своей порции, контекст сжали) |
| соблюдение (compliance) | доля случаев, где проверка guard или расширения держится | правило без замера — пожелание |
| вес | байты правил, которые стоит каждый ярус | видно, во что обходится вход сессии |
| повторная подача | правило пришло второй раз за отрезок сессии или после того, как модель прочитала файл сама | лишний вес в контексте |

## Дополнения

Выключены по умолчанию, включаются ключом в `desk.yml` → [extras.md](extras.md).

| Понятие | Что это | Зачем |
| --- | --- | --- |
| нить | то, что живёт дольше сессии: намерение («давай потом»), разбор без решения. Файл `threads/<slug>.md` с разделом следующего шага плюс строка в `now.md`; `now.md` — правило яруса `session` | сказанное в одном чате известно в следующем: каждая сессия начинается со списка открытого |
| журнал | строка `дата · репозиторий · заголовок` на выходе из сессии, хвост — на старте | новая сессия видит, что делалось вчера |
| мета | сигнал шапки, когда доля сессий про сам desk за неделю выше цели (`meta_goal`) | настройка правил не должна съедать работу |
| шапка | первый блок сессии: место, вес поданного, сигналы дополнений | видно, в каком контексте и с чем началась сессия |
| база, интеграционная ветка | ветка, куда вливаются задачи (`develop`); у места задаётся в `branches:` | новая работа начинается со свежей базы, а не с чужой старой ветки |
| чекаут к базе | строка на старте «на базе / не на базе»; с `auto` хук сам переводит чистый запушенный чекаут на базу | основной чекаут не изображает работу, которой в нём нет |
| дерево сессии | git worktree в `<чекаут>/.claude/worktrees/<имя>` от свежей базы | параллельные сессии не мешают друг другу в одном каталоге |
| свод деревьев и стеков | на старте — git worktree и docker-стеки с вердиктом | деревья и стеки копятся и держат гигабайты; свод говорит, что можно убрать |
| вердикт дерева | `держит работу` — единственная копия здесь (незакоммиченное, незапушенное); `в работе` — задача ветки в работе; `свежая работа` — трогали недавно или там идёт процесс; `сносимо` — остальное | снос только того, что нигде больше не нужно |
