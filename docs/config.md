# `desk.yml` — настройки движка

Необязательный файл в корне `DESK_HOME`. Отдельно от правил: правила яруса `import`
грузятся в каждую сессию целиком и не должны везти данные движка. Термины —
в [понятиях](concepts.md).

```yaml
portable: ['desk.md', 'process/**']   # переносимый слой — без имён мест
entry: '~/.claude/CLAUDE.md'          # файл с @-импортами: desk lint сверит их с ярусом import
triggers: {…}                         # общие триггеры, см. «when:»
require_tier: ['process/*.md']        # desk lint: у этих файлов обязателен tier
interfaces: {local: 'как поднять', …} # desk lint: допустимые имена файлов репозитория
```

- **`portable`** — правила, которые не привязаны к месту работы: их можно унести на
  новую работу или опубликовать, поэтому имена места (`place-words.txt`) в них
  не пропускаются.
- **`interfaces`** — одна раскладка для всех репозиториев. Файл
  `contexts/<место>/projects/<репо>/local.md` у каждого репозитория значит «как поднять
  локально», `tests.md` — «как гонять тесты» и так далее; общее правило ссылается на
  «`local.md` проекта», не зная, какой репозиторий в сессии. Поэтому в `projects/<репо>/`
  допустимы только имена из словаря, и файл с одним именем везде приходит одним ярусом.

`contexts/<место>/desk.yml` — триггеры места под теми же именами: они дополняют корневые,
пока место активно. Переносимое правило пишет `when: [tracker]`, а какой CLI или API
считается трекером, говорит место; где место триггер не определило, правило молчит.
Там же ветки места — `branches: {integration, production, repos: {<репо>: …}}`: по ним
на старте видно, на базе ли чекаут, и какой командой его привести.
